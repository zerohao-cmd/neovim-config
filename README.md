# Neovim 配置与使用说明

面向 WSL / Linux 的 Python、Rust 开发配置，使用 Neovim 0.12.6 验证。
新环境安装步骤见 [INSTALL.md](INSTALL.md)。终端运行 `nvim 文件路径` 或 `nvim .`。
在 Neovim 内输入 `:NvimGuide` 查看本说明。

## 普通模式：精简按键表

普通代码/文本编辑窗口采用按键白名单，未列入的常用字符、数字、Ctrl 组合键和功能键已禁用。
不再使用空格 Leader。原来的 `hjkl`、`yy`、`p`、`gd`、`K` 等操作不再保留；`v` 改为粘贴。
后续按实际需要逐个添加。鼠标仍可定位和切换窗口。

| 按键 | 操作 |
| --- | --- |
| ↑ ↓ ← → | 移动光标；浮窗打开时 ↑ ↓ 改为滚动浮窗 |
| Ctrl+← / Ctrl+→ | 上一个 / 下一个词的开头 |
| Home / End | 行首第一个字符 / 行尾 |
| PageUp / PageDown | 向上 / 向下移动 4 行，到文件边界停止 |
| Enter | 跳转定义（w 已禁用） |
| Tab / Shift+Tab | 当前行增加 / 减少一级缩进（4 个空格） |
| q | 打开 / 关闭文档和类型说明 |
| Q（Shift+q） | 打开 / 关闭定义源码预览 |
| e / E（Shift+e） | 光标跳转历史后退 / 前进 |
| / | 输入搜索内容，Enter 执行搜索，Esc 取消 |
| n / N（Shift+n） | 下一个 / 上一个搜索结果 |
| i | 进入插入模式 |
| z | 进入可视模式，选择文本 |
| xx | 剪切当前整行 |
| cc | 复制当前整行 |
| v | 在当前光标后粘贴内容，即使复制的是整行也不另起一行 |
| V（Shift+v） | 在当前行下方新增一行并粘贴内容 |
| dd | 删除当前整行 |
| u | 撤销上一次更改，可连续使用 |
| U（Shift+u） | 重做刚撤销的更改，可连续使用 |
| [ / ] | 折叠 / 展开光标所在的代码块（一级） |
| f | 格式化当前文件；Python 固定使用 Ruff |
| s | 打开或聚焦项目终端，自动进入命令输入状态 |
| o | 用 Oil 打开当前文件的父目录 |
| g | 打开当前文件的 Git diff 预览 |
| : | 进入命令行模式 |
| Esc | 关闭文档/源码浮窗；退出 diff 预览；否则清除搜索高亮 |

`q`、`Q`、Enter 需要当前文件的语言服务已连接。
`q` 和 `Q` 各自按一次打开、再按一次关闭；两个键之间切换会显示相应内容。
浮窗打开时，↑ / ↓ 逐行滚动内容，焦点和光标仍留在原文件；关闭后，↑ / ↓ 恢复移动源码光标。
Esc 或移动源码光标（例如 ← / →、跳词、Home / End、翻页或鼠标定位）都会退出预览。
`Q` 载入完整目标文件并定位到定义，不再截断长定义；浮窗标题标明文件和定义行号。
`e` / `E` 使用 Neovim 的跳转记录，记录定义跳转、搜索等位置，不记录每次方向键移动。
Tab 已改为缩进，E 仍然独立执行跳转前进，不会触发缩进。

代码折叠使用 Treesitter 的语法结构，支持 Python、Rust 等已安装解析器的语言。
打开文件时默认全部展开；普通模式按 `[` 折叠当前块，`]` 展开一级。插入模式仍正常输入方括号。
Git diff 单栏预览保持完整展开。

## 各模式共用的光标操作

普通、插入、可视模式及 Git diff 单栏预览均支持：↑ ↓ ← →、Ctrl+← / Ctrl+→ 跳词、
Home / End 行首行尾、PageUp / PageDown 向上 / 向下移动 4 行。
可视模式中移动会扩展或缩小选区；插入模式中移动后继续输入。
文档或源码预览打开时，上下键仍优先滚动浮窗。

普通、可视模式和 diff 使用 `e` 后退、`E` 前进。可视模式中的历史跳转会先结束选区。
插入模式中的 `e/E` 正常输入字母，需要历史跳转时先按 Esc，再用 `e/E`。

## 选择、复制与剪切

普通模式按 `z` 进入字符可视模式，当前字符也在选区中。方向键扩展或缩小选区，可跨行选择。
Ctrl+← / Ctrl+→ 按词扩展选区，Home / End 选到行首 / 行尾，PageUp / PageDown 每次移动 4 行。

- 可视模式按 `c` 复制选区，按 `x` 剪切选区；两者都会返回普通模式。
- 可视模式按 `Esc` 取消选择，文本保持不变。
- 普通模式按 `cc` 复制当前整行，`xx` 剪切当前整行。
- 普通模式按 `v` 始终从光标后粘贴；按 `V` 始终从当前行下方的新行开始粘贴。多行内容保留内部换行。

这里使用 Neovim 默认寄存器。`z` 仅在普通模式启动选择，插入模式仍正常输入字母。
`dd` 删除的整行也会进入默认寄存器，可用 `v` 在光标后粘贴，或 `V` 粘贴到下方新行。
单独按 `d`、`x` 或 `c` 不会修改文本，它们等待第二次按键组成 `dd`、`xx`、`cc`。

## 输入与自动补全

`i` 进入插入模式，`Esc` 回到普通模式并自动保存有改动的普通文件。普通模式按键表不会占用插入模式的字符输入。

补全只在输入变化时自动弹出。菜单出现后：

- Tab / Shift+Tab 或 Ctrl+n / Ctrl+p：选择候选项。
- Enter：确认已选候选项；没有选择候选项时正常换行。
- Ctrl+e：关闭菜单，继续输入可再次自动弹出。
- ↑ / ↓：关闭补全菜单并移动源码光标，不选择候选项。

没有手动唤醒入口：菜单关闭时 Ctrl+n / Ctrl+p 不触发补全，Ctrl+Space 和 Ctrl+x 补全前缀已禁用。
插入模式的 Ctrl+s 手动签名提示也已禁用；先 Esc，再按 q 查看文档和类型。

## 自动保存与外部同步

退出 Insert 模式（通常按 Esc）时，自动保存当前有改动、有文件路径且可写的普通文件。
已命名的新文件也会保存；未命名缓冲区、只读文件、Oil 面板、diff 和其他插件面板不会自动保存。
普通模式下的 `dd`、`u/U`、剪切、粘贴和 `f` 格式化不单独触发保存，可以用 `:w`，或在下次退出 Insert 时保存。

回到窗口、切换文件、普通模式光标停留及进入/退出 Insert 时，会检查磁盘上的外部变化。
当前缓冲区没有未保存修改时自动重新加载。它不是多人实时协同编辑，也不会拉取远程 Git。

如果你和外部程序都修改了文件，自动保存会暂停并提示，保留编辑器中的修改和磁盘版本，
不会自动合并或强制覆盖。检查冲突后再手动处理和保存。写入失败也会提示并保留未保存内容。
Git diff 预览仍是快照，关闭后重新按 `g` 刷新。

## 保存、退出和文件管理

- `:w` 保存，`:q` 退出，`:wq` 保存并退出。
- 普通模式按 `o` 用 Oil 打开当前文件的父目录；未命名缓冲区打开当前工作目录。也可以输入 `:Oil`，或从终端运行 `nvim .`。
- Oil 使用独立面板按键：Enter 打开条目，`-` 返回上级，q 关闭，g? 查看帮助。
- 在 Oil 中编辑文件名可重命名，新增一行可创建文件，名字以 `/` 结尾可创建目录。
- `:w` 提交目录修改，并确认操作预览。删除会直接删除文件，不送回收站。

精简按键表只作用于普通编辑缓冲区。Oil、帮助、插件管理器保留各自的面板操作。
Git diff 单栏预览共用搜索和光标移动键，内容只读。
搜索和 `:` 命令行中的编辑操作不受普通模式白名单限制。

## 内置终端

普通模式按 `s` 打开底部占编辑区域约 60% 高度的终端，自动进入终端输入状态。
每次打开或聚焦时，根据当前屏幕大小重新计算高度。
首次启动目录优先使用 Git 仓库根目录，否则使用最近的 Python/Rust 项目目录，再否则使用当前文件目录。
每个项目复用一个终端，隐藏后再次打开会保留进程、环境变量、命令和输出，不会重置当前 shell 目录。

- 终端输入状态：字母 `s` 正常交给 shell 或终端程序。
- 按 `Esc`：退出终端输入、隐藏终端并回到代码的 Normal 模式，原进程继续运行。Esc 由 Neovim 接管，不再传给终端内的程序。
- 按 Ctrl+\，松开，再按 Ctrl+n：进入终端的普通模式。
- 终端普通模式按 `s` 或 `Esc`：隐藏终端并返回代码；进程继续运行。
- 终端普通模式按 `i`：继续输入命令。
- 终端普通模式可以使用共用光标移动键、`/` 搜索、`n/N`，也可 `z` 选择、`c` 复制输出。
- 直接用鼠标点击代码窗口也可返回编辑；终端保持可见。
- shell 中输入 `exit` 会结束进程，下次从代码按 `s` 会启动新的终端。

## Git diff

普通模式按 `g`，在独立的全宽单栏窗口中查看当前文件。没有目录树、文件清单、统计标题或左右分栏。
显示完整文件，不折叠未修改部分；打开时定位到原光标对应的代码位置。

- 未修改行：正常显示。
- 删除行：红色背景和文字，左侧 `-` 标记。
- 新增行：绿色背景和文字，左侧 `+` 标记。
- 替换代码：先显示红色旧行，再显示绿色新行。

比较基准是 Git 暂存区（与普通 `git diff` 的基准一致），另一侧是当前编辑缓冲区，包含尚未保存的修改。
未跟踪的新文件全部显示为新增；没有变化时仍显示完整文件。已暂存且此后没有修改的内容不会重复标为差异。
打开预览不会保存文件，也不会暂存或修改代码。预览是打开时的快照，关闭后重新按 `g` 刷新。

`/` 输入搜索，Enter 确认，`n` 下一个、`N` 上一个结果；红色删除行也可搜索。
方向键、Ctrl+左右跳词、Home/End、PageUp/PageDown 每次 4 行及 `e/E` 跳转历史与普通模式一致。
`Esc`、再次按 `g` 或 `:q` 关闭预览，返回原编辑窗口和光标位置。`z` 可以选择预览文本，`c` 复制。

需要其他 Git 视图时，原 Diffview 插件仍可通过命令使用：`:DiffviewOpen` 查看仓库，
`:DiffviewOpen --cached` 查看暂存区，`:DiffviewFileHistory %` 查看文件历史。行旁的 Git 改动标记继续显示。

## Rust / Python

使用 Tokyo Night 配色、Treesitter 语法高亮和 LSP 语义高亮。
Rust 由 rust-analyzer 提供跳转、文档、补全和诊断；项目应有 Cargo.toml。
已为当前 stable 工具链安装 rust-analyzer、rust-src、rustfmt。
如果项目指定其他工具链，请在项目目录运行 `rustup component add rust-analyzer rust-src rustfmt`。
首次打开大型项目需要等待索引及 Cargo 检查。

Python 使用 Pyright。按顺序选择已激活的 virtualenv、Conda 环境、项目 `.venv` / `venv`，最后使用系统 python3。
推荐先运行 `source .venv/bin/activate`，再启动 Neovim。
已安装 Ruff 0.17.4（通过 `uv tool install ruff`），与 Pyright 同时启用。
Pyright 继续负责补全、定义跳转、文档和类型检查；Ruff 提供规范检查、代码操作及格式化。
Ruff 的 hover 已关闭，`q` 的文档和类型说明仍由 Pyright 提供。

普通模式按 `f` 格式化当前整个文件。Python 只调用 Ruff；Rust 等其他语言调用已连接且支持格式化的语言服务。
Ruff 遵循项目的 `pyproject.toml`、`ruff.toml` 或 `.ruff.toml` 配置。
`f` 只格式化，不执行批量 lint 修复或自动删除未使用的导入；可以按 `u` 撤销格式化。
格式化后用 `:w` 保存，或在下次退出 Insert 时自动保存。没有配置保存时自动格式化。

## 配置与维护

- 主配置：`~/.config/nvim/init.lua`
- 项目终端：`~/.config/nvim/lua/project_terminal.lua`
- 自动保存与外部变化检查：`~/.config/nvim/lua/file_sync.lua`
- 当前文件单栏 diff：`~/.config/nvim/lua/inline_diff.lua`
- 精简按键与源码预览：`~/.config/nvim/lua/minimal_keys.lua`
- 插件版本锁：`~/.config/nvim/lazy-lock.json`
- 插件目录：`~/.local/share/nvim/lazy/`
- 查看插件：`:Lazy`；更新插件：`:Lazy sync`；更新语法解析器：`:TSUpdate`
- 查看语言服务：`:checkhealth vim.lsp`；整体检查：`:checkhealth`
- 更新 Ruff：`uv tool upgrade ruff`
- 更新 Pyright：`npm install -g --prefix ~/.local pyright`

日常启动和已安装的语言功能使用本地依赖。插件更新、下载解析器和未缓存的 Cargo 依赖需要网络。
